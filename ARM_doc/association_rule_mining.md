# Association Rule Mining

This document details the Association Rule Mining (ARM) process, algorithm evaluation, holdout validation, and redundancy pruning for NYC taxi demand forecasting.

---

## 2. Objective & Rule Constraints

The objective is to discover predictive associations between environmental/spatio-temporal conditions and taxi pickup demand levels.

- **Consequent Constraint:** Strictly single-item demand targets: `consequents ∈ {demand=High, demand=Medium, demand=Low}`.
- **Antecedent Constraint:** Environmental and spatio-temporal features only (`time_band`, `zone_cluster`, `day_type`, `temperature`, `rain`, `snow`, `holiday`). `demand=` items are prohibited in the antecedent.
- **Metric Thresholds:**
  - Minimum confidence: `0.50` (at least 50% conditional probability)
  - Minimum lift: `1.20` (at least 20% lift over baseline independent occurrence)

---

## 3. Algorithms Evaluated: Apriori vs. FP-Growth

Both algorithms were run on the training data across minimum support values of `0.05`, `0.01`, and `0.005` to evaluate computational scalability and consistency.

### Methodological Comparison

| Aspect | Apriori | FP-Growth |
|---|---|---|
| **Frequent Itemset Strategy** | Candidate generation (join and prune step) | Frequent Pattern Tree (FP-Tree) structure |
| **Database Scans** | Multiple passes over transactions (one per itemset size) | Exactly two passes to build and traverse the FP-tree |
| **Output Equivalence** | Produces exact same itemsets and rules | Produces exact same itemsets and rules |
| **Runtime @ min_support=0.005** | ~28.5 seconds | ~1.2 seconds (~24x speedup) |
| **Candidate Demand Rules @ 0.005**| 897 rules | 897 rules |

**Selection:** FP-Growth at `min_support = 0.005` was selected as the engine for all downstream steps because it provides mathematical parity with Apriori while scaling significantly faster as support thresholds decrease.

## 4. Holdout Test Validation

Rules were mined exclusively on the training split (October–December 2024, 320,544 rows). Each rule was then re-evaluated on the unseen holdout test split (January 2025, 80,256 rows).

### Stability Filters
A rule was retained as **Holdout-Stable** if it met three criteria on the test data:
1. `test_antecedent_count >= 100`: Prevents seasonal sample starvation (e.g. summer temperature conditions that never occur in winter).
2. `test_confidence >= 0.50`: Confirms reliability on unseen data.
3. `test_lift >= 1.20`: Confirms positive association above baseline independence.

**Result:** Of the 897 mined candidates, 632 met all stability criteria. 265 rules were dropped due to low test counts or seasonal dropout.

---

## 5. Redundant Rule Elimination (Pruning)

Association rule mining generates combinatorial variations where uninformative features attach to an already valid rule.

### Pruning Criterion
A specific rule $R_2: A_2 \implies C$ is defined as **redundant** relative to a general rule $R_1: A_1 \implies C$ if:
1. Both rules predict the exact same consequent $C$.
2. Antecedent $A_1$ is a strict proper subset of $A_2$ ($A_1 \subset A_2$).
3. Rule $R_2$ provides no confidence gain over rule $R_1$ ($\text{conf}(R_2) \le \text{conf}(R_1)$).

### Pruning Results
- **Redundant Rules Removed:** 480 rules.
- **Clean Rules Retained:** 152 non-redundant decision rules.

### Features Dropped During Pruning
Analyzing the difference set ($A_2 \setminus A_1$) identifies which features were discarded:
- **Weather Features (49.7% of drops):** `snow` (73 drops), `temperature` (63 drops), `rain` (51 drops). In the vast majority of hours, weather is normal (`snow=no`, `rain=no`); appending these conditions added no predictive gain.
- **Calendar Baselines (38.8% of drops):** `day_type` (77 drops), `holiday` (69 drops). Tacking on `holiday=regular` or weekday flags added zero information over the base time band.
- **Spatial Clusters (11.4% of drops):** `zone_cluster` (43 drops).
- **Temporal Bands (0.0% of drops):** `time_band` was never dropped, serving as the core anchor across all predictive rules.
